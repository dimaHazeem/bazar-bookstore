8. Performance Measurement Results

Experiment setup:
The system was deployed using Docker Compose with one frontend service, two catalog replicas, and two order replicas. The frontend used round-robin load balancing and an in-memory cache for info requests.

| Experiment                     | Average Response Time (ms) | Minimum (ms) | Maximum (ms) |
|-------------------------------|----------------------------|--------------|--------------|
| Info without cache            | 32.61                      | 11.92        | 261.31       |
| Info with cache               | 2.35                       | 1.34         | 5.41         |
| Purchase request              | 97.55                      | 73.33        | 234.96       |
| Cache invalidation write      | 72.12                      | 72.12        | 72.12        |
| Cache miss after invalidation | 8.54                       | 8.54         | 8.54         |

Conclusion:
Caching significantly improved read request latency. The average info request without cache was 32.61 ms, while the average info request with cache was 2.35 ms. Purchase requests took longer because they involve the order service, catalog service, database update, cache invalidation, and replica synchronization.
